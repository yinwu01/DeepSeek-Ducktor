道理：几个月后最常要复现你结果的人，就是你自己。说不清一个数字是哪版代码、哪组配置、哪份数据、哪个种子跑出来的，有人质疑时，你既查不出是不是 bug，也重跑不出来。
怎么用：每次运行建一个带日期的目录，存下代码的提交号（以及当时是否有未提交的改动）、完整配置、完整命令行、数据的版本或校验值、随机种子、依赖环境、日志和指标文件；实验笔记按日期写做了什么、为什么、结果怎么看。结果表用脚本从结果文件生成，不手抄。agent 给你一张结果表时，随手挑一两个数字，问它出自哪次运行 → 打开那个目录，对上提交号、配置和种子 → 切回那个提交重跑，至少用存下的模型重跑一遍评测，看数字对不对得上。追不回来的数字，不进论文。
外面：
- Sandve 等：每个结果都记下是怎么来的，包括程序版本、参数和输入；自写脚本全部做版本管理；有随机性的分析记下种子；避免手工改数据，也别在文档之间复制粘贴；文中每句结论都要能连回它依据的那个具体结果。
- Noble：核心原则是不熟悉项目的人看你的文件就能明白你做了什么、为什么，而这个人最常是几个月后的你；实验目录按日期组织，配一份按日期写的实验笔记，用一个驱动脚本记下每一步操作。
- Pineau 等：复现指用同样的代码和数据得到相近的结果；配套的机器学习复现清单（v2.0）要求写出超参的范围、选超参的方法和最终配置，训练和评测的确切运行次数，数据划分，以及计算环境。
- Papers with Code 代码完整性清单：依赖说明、训练代码、评测代码、预训练模型，以及 README 里的结果表，配上能跑出这些数字的确切命令。
