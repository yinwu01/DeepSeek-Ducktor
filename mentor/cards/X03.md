道理：几个月后最常要复现你结果的人，就是你自己。说不清一个数字出自哪版代码、哪组配置、哪份数据、哪个种子，有人质疑时，你既查不出是不是 bug，也重跑不出来。
怎么用：每次运行建一个带日期的目录，存提交号（和当时有没有未提交的改动）、完整配置和命令行、数据版本或校验值、种子、依赖环境、日志和指标；为什么这么跑，记在研究日志里（见 A01）。结果表用脚本从结果文件生成，不手抄。agent 交来结果表时，挑一两个数字问出自哪次运行 → 打开目录对上提交号、配置和种子 → 用存下的模型在同一环境下重跑评测，数字应该一样。重跑训练在 GPU 上常对不到每一位，落在种子间的波动内（见 E05）就算对上。追不回来的数字，不进论文。
外面：
- Sandve 等：每个结果记下用的程序版本、参数和输入；脚本全部做版本管理；有随机性就记种子；别手工改数据，别在文档之间复制粘贴。
- Noble：不熟悉项目的人看你的文件就该明白你做了什么、为什么，这个人最常是几个月后的你；实验目录按日期组织，用驱动脚本记下每一步。
- Pineau 等：复现指用同样的代码和数据得到相近的结果；Pineau 的复现清单要求写出超参范围和挑法、运行次数、数据划分、计算环境，代码的 README 要配上能跑出每个结果的命令。
