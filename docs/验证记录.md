# 验证记录

2026-10-25，在一台 Linux x64 机器上做。插件版本 0.1.0，Doctor Duck 345d618（`duck.lock.json`）。

## 环境

- DeepSeek Harness：npm 上的 `@deepseek-ai/dsh@0.2.1-rc.2`（`latest`）和 `0.2.1-rc.3`（`next`），用 `npm install -g --ignore-scripts` 分别装进两个独立目录；Node 24.22.1。
- 每次运行都在新的网络命名空间里（`unshare -cn`，只有 loopback），`env -i` 清空环境，HOME 是临时目录，没有 `DEEPSEEK_API_KEY`，dsh 遥测关掉。
- 没有 key，dsh 在发模型请求之前报 `MISSING_CREDENTIAL` 停下；这时会话日志里已经写好了这次请求要带的全部消息。下面所有「注入了什么、在哪个位置」都是从 dsh 自己的会话日志（`session.v4.jsonl.zstd`）里读出来的。整个验证没有东西出本机，也没有调用任何模型。

## 自动检查：`tests/dsh/check.mjs`

| 检查 | rc.2 | rc.3 |
|---|---|---|
| `--route pnpm --web`：`dsh plugin --profile headless/web add`，headless 和 web 的全部检查，再 `remove` | 20/20 | 20/20 |
| `--route patch --web`：`~/.dsh/cordis.patch.yml` 一行，同上，再删掉这一行 | 17/17 | 17/17 |
| `--route ui`：在运行中的 `dsh web` 里调插件页用的 `pluginManager/installBundle`（填仓库绝对路径）、`listBundles`、`removeBundle` | 9/9 | 9/9 |

逐项检查的是：

- 装上以后，组合出来的 profile 里有 `deepseek-ducktor` 这一行。
- headless 里 `/duck 菜单`（开关 on）：会话里的消息顺序是 学生消息 → Doctor Duck 开场说明 → dsh 的 runtime context → `/duck` 命令正文。开场说明和 Doctor Duck 的 `bin/duck.js` 给这个项目生成的文字逐字相同（外面套 `<system-reminder>`，后面加 DeepSeek Harness 的工具对照），带常驻规则。`/duck` 命令正文里的 Base directory 是 Doctor Duck 根目录。
- 同一个会话接着敲 `/duck-why`：没有第二份开场说明。
- 把开关改成 quiet 再接着说话：进来一份替换的开场说明，开头写明它替换前面那份。
- 开关 off 的新会话：开场说明是 Doctor Duck 的 off 说明。
- web 里：`skills/list` 列出 14 条命令，全部「只能学生敲」，路径是真实的 SKILL.md；在 standard 预设的会话里发 `/duck-review 帮我看看`，开场说明在学生消息之后、命令正文之前（web 的预设在命令之后还会加一条时间信息）。
- 插件页路线：装上后 `listBundles` 里有它，标题、描述是 `locale/` 里写的；不重启，新会话的 `skills/list` 里就有命令；卸载后，不重启，新会话里就没有了。
- 卸载以后：profile 里没有这一行，会话里没有开场说明、没有 `/duck` 命令。

## 手动核对过的

- 两种方式同时在（profile 里装了，`~/.dsh/cordis.patch.yml` 也有同 id 的一行）：只有一行起作用，是 home 级那一行。证据：给那一行加 `sessionContext: false`，开场说明就没了。所以不会注册两遍，设置以 home 级那一行为准。
- 开场说明的长度：没开启 1812 字符，on 3834，quiet 3840，off 1808。
- 端到端驱动 `tests/e2e/flow.cjs` 在没有 key 时：第一阶段的检查「开场注入的是没开启的说明，不是常驻规则」在真实会话日志上通过；随后在 `MISSING_CREDENTIAL` 处干净停下，不往后跑。设 `DUCK_E2E_MODEL=deepseek-v4-pro` 后，会话里记录的模型从默认的 `deepseek-flash` 变成 `deepseek-v4-pro`。
- 插件页详情：rc.2、rc.3 还不读 `meta.detail`（只读标题和描述，多出的字段不报错）。用 dsh 主干源码（22ddee379，2026-10-23）里的读取函数读本仓库：界面语言 zh-CN、zh 取 `docs/DETAIL.zh.md`，en、ja 取 `docs/DETAIL.md`。
- 会话中途工具调用之后补发的开场说明：dsh 在每一步之前才收集要进来的消息，这时工具结果已经写进历史，所以补发的说明在工具结果之后，不会插到 assistant 的 tool_calls 和 tool 结果之间（读 dsh 源码 `agent-loop/src/agent.ts` 确认，和 dsh 自己的 AGENTS.md 加载器同一做法）。

## 没验证的

- 真模型下的效果：DeepSeek 模型是否照 Doctor Duck 的规则做事、整套学生流程能过几项。需要一个 DeepSeek API key，跑 `tests/e2e/flow.cjs`。
- Desktop：只有 macOS、Windows 版，这台是 Linux。README 里 Desktop 的两种装法照 dsh 文档写，没跑过；方式三（home 级那一行）在 Desktop 里能不能加载 dsh 自带的包，没把握，Desktop 用户请用插件页。
- 插件页的点击流程本身：测的是插件页调用的后端接口，没在浏览器里点过；插件的「配置」页长什么样也没看过。
- 对话压缩后重发、子代理默认不带：只有单元测试。压缩和子代理都要真模型才能触发。
- acp、sdk、sdk-minimal 这几个 profile：没测。home 级那一行对它们也生效，理论上一样，没跑过。
- Windows 路径：代码里转了路径分隔符，没在 Windows 上跑过。

## 复现

```sh
npm test
node tests/dsh/check.mjs --route pnpm --web
node tests/dsh/check.mjs --route patch --web
node tests/dsh/check.mjs --route ui
```
